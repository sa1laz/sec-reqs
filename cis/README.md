# CIS Benchmarks в машиночитаемом виде

Локальная база рекомендаций CIS Benchmarks для сверки конфигураций и поиска пробелов.
Только для внутреннего некоммерческого использования: исходные PDF распространяются CIS
по лицензии CC BY-NC-SA 4.0, а условия CIS запрещают выкладывать бенчмарки на внешние сайты.
Не публиковать ни PDF, ни разобранные данные: в git попадают только скрипты и каталог WorkBench
(названия и версии), а `pdf/`, `benchmarks/` и `cis.db` собираются локально и исключены через `.gitignore`.

Срез на 2026-11-14: 346 бенчмарков в последних опубликованных версиях, 42 319 рекомендаций.

## Состав

| Путь | Что это |
|---|---|
| `benchmarks/index.json` | список разобранных бенчмарков: название, версия, дата, число рекомендаций, путь |
| `benchmarks/<slug>/benchmark.json` | метаданные, определения профилей, дерево разделов с описаниями |
| `benchmarks/<slug>/recommendations.jsonl` | одна рекомендация на строку |
| `catalog_latest.json` | 355 бенчмарков WorkBench в последней опубликованной версии |
| `catalog_all_published.json` | все 692 опубликованные записи, включая старые версии |
| `download_manifest.json` | какой PDF взят для каждого бенчмарка (ID файла в WorkBench) |
| `no_pdf.json` | 7 бенчмарков, у которых в WorkBench нет PDF |
| `pdf/<workbench_id>.pdf` | исходные PDF (~835 МБ) |
| `qa_report.json` | проверка качества по каждому бенчмарку |
| `parse_cis_pdf.py` | разбор одного PDF |
| `build_all.py` | разбор всех PDF в `benchmarks/` |
| `qa.py` | проверка качества |
| `build_db.py` | сборка `cis.db` (SQLite + FTS5) для MCP-сервера |
| `cis.db` | база для MCP-сервера (~230 МБ) |

Пересобрать базу:

```
rm -rf cis/benchmarks && .venv/bin/python cis/build_all.py && .venv/bin/python cis/qa.py && .venv/bin/python cis/build_db.py
```

## MCP-сервер

Инструменты `cis_*` в общем MCP-сервере sec-reqs (`secreqs/sources/cis.py`), см. README в корне репозитория.
Сервер читает `cis.db` в режиме только чтения.

## Что не вошло

- 7 бенчмарков без PDF в WorkBench: Apache Tomcat 10.1, 11 и 9 STIG; Cisco Firewall; Debian 11 Branch;
  Fedora 34 Branch; VMware ESXi 6.7 Final Update.
- CIS Controls — это не бенчмарк, отдельный документ.
- Черновики, архивные и старые версии.

## Запись рекомендации

| Поле | Тип | Содержимое |
|---|---|---|
| `uid` | string | `cis:<workbench_id>:<номер>`, уникален в базе; при повторе номера в исходнике добавляется `#2` |
| `benchmark_id`, `benchmark`, `benchmark_version` | | к какому бенчмарку относится (название и версия — из каталога WorkBench) |
| `id` | string | номер рекомендации, например `4.3.1` |
| `title` | string | название без статуса проверки |
| `assessment_status` | string \| null | `Automated` или `Manual`; `null`, если в PDF статус не указан |
| `profiles` | string[] | профили применимости (`Level 1`, `Level 2 - Worker Node`, …) |
| `section_path` | object[] | цепочка разделов от корня: `number`, `title` |
| `description`, `rationale`, `impact` | Markdown | что, зачем, побочные эффекты |
| `audit` | Markdown | как проверить; команды в блоках кода |
| `remediation` | Markdown | как исправить |
| `default_value` | Markdown | значение по умолчанию |
| `additional_information` | Markdown | дополнительные сведения |
| `references` | string[] | ссылки и идентификаторы NIST |
| `cis_controls` | object[] | `version` (v8/v7), `control`, `title`, `description`, `ig1`–`ig3` |
| `mitre_attack` | Markdown | сопоставление с MITRE ATT&CK, если есть |
| `page_start`, `page_end` | int | страницы в PDF |
| `duplicate_number_in_source` | bool | есть только у записей, чей номер повторяется в самом PDF |

Пустые текстовые поля — `null`, пустые списки — `[]`.

## Качество

Проверка (`qa.py`) сравнивает число записей с числом блоков «Profile Applicability:» в тексте PDF
и с оглавлением PDF, если оно есть.

- Число рекомендаций совпало у 343 из 346 бенчмарков. Расхождение на одну запись у Apache HTTP Server 2.4,
  Ubuntu 20.04 v3.0.0 и Xylok Security Suite STIG.
- Где у PDF есть оглавление (233 файла), совпадение у 232.
- 305 бенчмарков без единого замечания. У остальных — единичные пустые поля; часть из них пуста
  и в самом PDF (например, в AWS Database Services процедура исправления записана в разделе аудита).
- У 1 393 рекомендаций нет статуса проверки: в Amazon Linux 2 v4.0.0, IBM AIX 7, RHEL 10 STIG и
  AlmaLinux 9 STIG статус в заголовках PDF не указан.
- В нескольких STIG-бенчмарках номера рекомендаций повторяются в исходнике; такие записи помечены.
- Содержимое проверено выборочно, не целиком.

## Как устроен разбор

- Заголовки находятся по вёрстке: рекомендация набрана курсивом 16pt, раздел — полужирным 12–16pt.
  Оглавление PDF не используется, оно есть не во всех файлах.
- Строчный код (моноширинный шрифт) обёрнут в обратные кавычки, блоки кода — в тройные.
- Строки команд, перенесённые вёрсткой PDF, склеиваются обратно: перенос распознаётся по тому,
  что первое слово следующей строки не поместилось бы на текущей.

## Известные ограничения

- Склейка перенесённых команд эвристическая. Если в PDF две короткие команды идут подряд и первая
  заканчивается у правого края, они могут склеиться в одну строку.
- Ошибки вёрстки самого PDF переносятся как есть.
- Таблицы внутри текстовых полей превращаются в обычный текст.
- Изображения не извлекаются.
